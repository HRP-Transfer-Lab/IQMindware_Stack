# G Track Working Memory Benchmark Protocol

Protocol version: `g-track-working-memory-v1`
App task version: `wmc-b10-v0.1.0`
Status: production protocol specification for the G Track app; non-diagnostic.

Copyright (c) 2026 HRP Transfer Lab. This protocol specification is released
under the MIT License. It describes the behavioral protocol and score
calculation at a cognitive-science level. It does not publish the application
source code.

## Scope

This protocol describes the Working Memory benchmark implemented in G Track.
The benchmark is assessment, not training. It estimates two working-memory
signals:

- Working Memory Capacity, using a visuospatial complex-span task.
- Binding Precision, using a token-location visual change-detection task.

The benchmark is intended for repeated pre-training, post-training, and
follow-up tracking alongside IQMindware training apps. It is not a clinical
test, diagnostic test, employment or school selection test, certificate, or IQ
score.

## Source Alignment

The Working Memory Capacity block is aligned with the automated Symmetry Span
task family. In Symmetry Span, participants alternate between a processing task
that requires judging whether an 8 x 8 matrix is vertically symmetrical and a
storage task that requires remembering locations in a 4 x 4 grid. The automated
complex-span literature supports partial-credit scoring, processing-accuracy
validity checks, and use of complex span as an individual-differences measure
of working memory capacity.

G Track uses internally generated stimuli and a browser-native implementation.
It does not copy third-party task code or reuse protected item files. Its
scored structure follows the standard automated Symmetry Span set-size pattern:

| Element | Source task family | G Track implementation |
|---|---:|---:|
| Processing stimulus | 8 x 8 symmetry judgement | 8 x 8 symmetry judgement |
| Storage stimulus | 4 x 4 spatial location | 4 x 4 spatial location |
| Scored sets | 12 sets | 12 sets |
| Set sizes | 2, 3, 4, 5 | 2, 3, 4, 5 |
| Sets per size | 3 | 3 |
| Scored serial positions | 42 | 42 |

The Binding Precision block is aligned with visual working-memory
change-detection and feature-binding paradigms. The task asks whether a probed
token at a location is the same as before or different. Swap-change trials are
the binding-specific trials: the probe token is familiar from the memory array
but belonged to a different location.

The binding block is a transparent G Track task specification, not a direct
copy of a single published test. Its standardization uses a visual
feature-binding literature prior and should be replaced by IQMindware
recalibration once enough valid G Track completions exist.

## Forms and Timepoints

The benchmark has three scheduled forms:

| Form | Default role |
|---|---|
| `wm-a` | Baseline / pre-training |
| `wm-b` | Post-training |
| `wm-c` | Follow-up |

The app can counterbalance form order in programme contexts, but the proof
payload keeps the measurement role separately as `baseline`, `post`, or
`follow_up`.

## Task Protocol

### Part A: Working Memory Capacity

The participant alternates between:

1. a symmetry judgement for an 8 x 8 black-and-white pattern;
2. a highlighted square in a 4 x 4 grid to remember;
3. serial recall of the highlighted grid locations at the end of the set.

Task schedule:

```text
Practice:
  2 sets: one size-2 set and one size-3 set.

Scored:
  12 sets.
  3 sets each at size 2, 3, 4, and 5.
  42 total scored serial positions.
```

Stimulus rules:

```text
Symmetry pattern:
  8 x 8 binary matrix.
  Symmetrical items are mirrored about the vertical axis.
  Asymmetrical items are generated by perturbing a valid symmetrical pattern.
  Black-cell density is constrained to avoid trivial sparse/dense patterns.

Storage location:
  one highlighted cell in a 4 x 4 grid per item.
  locations do not repeat within a set.
  simple row, column, and diagonal runs are rejected.
```

Timing and responses:

```text
Symmetry response window: 3000 ms.
Location display: 650 ms.
Recall: participant selects locations in serial order.
Desktop keys: F = symmetrical, J = not symmetrical.
Touch/button responses provide the same two choices.
No scored-trial feedback is given.
```

### Part B: Binding Precision

The participant sees a memory array of visual tokens at locations, waits
through a retention interval, then judges whether the probe token at one
location is the same as before or different.

Task schedule:

```text
Practice:
  6 trials at set size 3.

Scored:
  54 trials.
  Set sizes: 3, 5, 7.
  Conditions: same, novel_change, swap_change.
  6 repeats per set-size x condition cell.
```

Stimulus rules:

```text
Token set:
  8 internally generated token identities.
  each token combines colour with a simple pattern/mark.

Memory array:
  tokens are unique within the array.
  possible locations are selected from a 12-location display set.

Probe conditions:
  same: original token appears at the original location.
  novel_change: probe token was not in the memory array.
  swap_change: probe token was in the memory array, but at another location.
```

Timing and responses:

```text
Memory array display: 500 ms.
Retention interval: 900 ms.
Probe response window: 2500 ms.
Desktop keys: F = same, J = different.
Touch/button responses provide the same two choices.
No scored-trial feedback is given.
```

## Raw Scoring

All canonical scoring is performed server-side from submitted trial rows.
Practice trials are excluded.

### Complex-Span Scores

The primary complex-span raw score is partial-credit serial recall:

```text
complexSpanPCU = exact serial positions correct / total serial positions
```

Because the task has 42 scored serial positions:

```text
complexSpanPCU = exact serial positions correct / 42
```

Additional raw metrics:

```text
processing accuracy = correct symmetry judgements / symmetry items
processing omission rate = omitted symmetry judgements / symmetry items
processing median RT = median RT for non-omitted symmetry judgements
item accuracy = recalled target locations, ignoring order / total targets
whole-set accuracy = perfectly recalled scored sets / 12
absolute score = sum of set sizes for perfectly recalled scored sets
maximum stable set size = largest size with at least 2 of 3 perfect sets
transposition rate = target locations recalled in the wrong serial position / 42
intrusion rate = recalled non-target locations / 42
```

Validity rule:

```text
If processing accuracy < .75:
  Working Memory Capacity standard score is not issued.
  Confidence label is invalid/unstable.

If processing accuracy >= .75 and < .85:
  result may be labelled limited.

If processing accuracy >= .85:
  result is treated as usable for the validation-prior score.
```

### Binding Scores

Change is treated as the signal:

```text
Hit = different response on novel_change or swap_change trials.
False alarm = different response on same trials.
```

Signal-detection scores use log-linear correction:

```text
corrected hit rate = (hits + 0.5) / (change trials + 1)
corrected false alarm rate = (false alarms + 0.5) / (same trials + 1)
d-prime = z(corrected hit rate) - z(corrected false alarm rate)
response bias = -0.5 * (z(corrected hit rate) + z(corrected false alarm rate))
```

The binding block calculates:

```text
overall d-prime:
  novel_change and swap_change trials versus same trials.

novel d-prime:
  novel_change trials versus same trials.

swap d-prime:
  swap_change trials versus same trials.

swap cost:
  novel d-prime - swap d-prime.

balanced accuracy:
  mean(correct same rate, correct change rate).

exploratory K by set size:
  set size * (novel-change hit rate - same-trial false-alarm rate).
```

The public Binding Precision standard score uses swap d-prime because
swap-change trials specifically test token-location binding rather than only
detecting a novel token.

Validity rule:

```text
If binding omission rate > .10:
  Binding Precision standard score is not issued.
  Confidence label is limited.
```

## Public Standard Scores

The app displays estimated standardized working-memory scores on a 100/15
scale where available. These are non-diagnostic validation-prior scores:
100 is the reference mean, 15 points is one reference standard deviation, and
higher values indicate better performance in the scored direction.

### Working Memory Capacity

App field:

```text
publicScores.workingMemoryCapacity
```

Raw input:

```text
complexSpanPCU
```

Validation prior:

```text
source = Redick et al. (2012) automated Symmetry Span partial-score norms
N = 6,018
mean partial score = 27.87 / 42 = 0.6636 PCU
SD partial score = 8.26 / 42 = 0.1967 PCU
```

Score calculation:

```text
z = (complexSpanPCU - 0.6636) / 0.1967
z is clipped to [-3, 3]
standard score = 100 + 15*z
public display range = 55 to 145
```

The score is issued only when the processing-accuracy validity gate is passed.

### Binding Precision

App field:

```text
publicScores.bindingPrecision
```

Raw input:

```text
bindingDPrimeSwap
```

Validation prior:

```text
source = visual feature-binding change-detection literature prior
N = 90
mean swap-lure d-prime = 1.172
SD swap-lure d-prime = 0.56
```

Score calculation:

```text
z = (bindingDPrimeSwap - 1.172) / 0.56
z is clipped to [-3, 3]
standard score = 100 + 15*z
public display range = 55 to 145
```

This is a literature prior, not a stable population norm. It should be
replaced by IQMindware recalibration once the G Track sample is large enough.

### WM Composite

App field:

```text
publicScores.composite
```

Calculation:

```text
component z values =
  z(Working Memory Capacity), when valid
  z(Binding Precision), when valid

composite z = mean(finite component z values)
WM Composite standard score = 100 + 15*composite z
public display range = 55 to 145
```

The same composite is stored in the portable G Track proof score as
`provisionalIndex`. This is a compatibility field for history/proof views and
is not a separate psychological construct.

## Public Result Display

The G Track result screen displays:

```text
WM Composite:
  publicScores.composite or provisionalIndex.

Working Memory Capacity:
  publicScores.workingMemoryCapacity.displayStandardScore or standardScore.
  Secondary line: serial recall PCU and processing accuracy.

Binding Precision:
  publicScores.bindingPrecision.displayStandardScore or standardScore.
  Secondary line: swap d-prime and balanced accuracy.
```

When a component standard score is unavailable because validity gates were not
passed, the app may show the task band instead of a number.

Launch bands are descriptive task bands, not percentile bands:

| Working Memory Capacity PCU | Band |
|---:|---|
| below .50 | Low task performance |
| .50 to below .65 | Developing |
| .65 to below .80 | Standard range |
| .80 to below .90 | Strong |
| .90 and above | Very strong |

| Binding swap d-prime | Band |
|---:|---|
| below .50 | Low task performance |
| .50 to below 1.00 | Developing |
| 1.00 to below 1.50 | Standard range |
| 1.50 to below 2.00 | Strong |
| 2.00 and above | Very strong |

## Recalibration Policy

The current standard scores are validation-prior estimates. IQMindware
recalibration should replace these priors when enough valid baseline G Track
data have accumulated to estimate:

- score distributions;
- form effects;
- retest and practice effects;
- device/browser effects;
- age or sample-composition effects, if justified;
- uncertainty around individual change.

Baseline/pre-training attempts are the appropriate norm-building source.
Post-training and follow-up attempts are saved and exportable for personal
change evidence, but should not be mixed into baseline norm estimates.

## Interpretation Boundary

Use these outputs for coaching and self-monitoring only. Do not use them for:

- diagnosis;
- treatment decisions;
- employment, school, or selection decisions;
- certificates, rankings, or claims of general intelligence;
- claims that a short browser-based test is a complete model of working
  memory;
- claims that the binding prior is a population norm before IQMindware
  recalibration supports that claim.

The safest interpretation is: a short, browser-based working-memory benchmark
that estimates complex-span maintenance-under-processing and visual
token-location binding as provisional, non-diagnostic coaching signals.
